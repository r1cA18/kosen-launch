# 交流と機会の実装

2026年11月6日。作品を見せるだけで終わらせず質問と役割のある誘いにつなげる。SNSの公開範囲は作品公開とは別の「ホームにも共有する」で選ぶ。

## 利用の流れ

1. 共有作品の「質問・一緒に活動」から公開の質問を送信
2. 作者が返信して質問者の交流画面に通知
3. 活動名と募集URLと双方の役割と最初の一歩を添えて相手を誘う
4. 相手が受け入れるか見送る。送信者は返事前に取り消せる
5. 受け入れ後に双方が選んだ連絡先URLを二人だけに共有
6. 機会の画面にイベントを保存して参加状況と準備を管理

誘いの受け入れは応募や参加の確定を意味しない。共有する連絡先を空欄で保存すると取り消せる。公開停止とホーム共有の解除とブロックでは誘いを取り消し連絡先を消去する。再公開やブロック解除で以前の連絡先は復活しない。

公開作品にはログインしていない人も質問と作者の返信を閲覧できる。書き込みには本人セッションと同一Originが必要。MCPのBearerトークンでSNSへ発信できない。ブロックは交流を止める機能であり匿名の公開ページ閲覧を拒む機能ではない。

質問は質問者と作品の作者が削除できる。通報すると通報者の画面では質問を隠して`social_reports`に理由を保存する。運営向けの通報処理画面や人員の運用は未整備。外部公開前に対応手順を用意する。質問は一時間20件までで誘いは一日10件まで。古い質問が多い場合は最新100件を表示する。

## 制作ログのタイムライン

ホームはX型の1カラム時系列で、制作の進み具合を見せる、仲間を募る、質問する用途に絞る。リポストとフォロワー数とおすすめ表示は作らない。

- 進捗：280字まで。自分が公開中の作品を1件添付でき、コンパクトなカードで埋め込む。公開停止した作品は埋め込みを表示しない
- 仲間募集：活動名と本文と求める役割（最大8個）と任意の募集URL（http・httpsのみ）と締切。締切を過ぎると参加希望を受け付けない
- 作品の共有：「ホームにも共有」した作品が共有イベントとして並ぶ。既存の気になるを使う
- 絞り込み：すべて、仲間募集、役割タグ。役割タグは直近の募集から生成する
- 操作：気になる（件数表示）、返信（1段。投稿詳細`/timeline/:id`で表示。返信への返信は不可）、削除（作者。返信は投稿者も削除可）、通報、ブロック
- 参加したい：役割と添える公開作品（任意）と一言を送る。募集者が受け入れると連絡先URLを双方が選んで相手だけに共有する。受け入れ前は募集者と申込者だけが見える。誘いのinvitationは作品に紐づくため、同じ規則（返事は受け手のみ、取り消しは送り手のみ、ブロックで取り消して連絡先を消去）で`timeline_joins`を新設した
- 通知：返信と参加希望と返事を既存の未読数に合算する（`timeline_notices`）。投稿自体は受信者がいないため通知しない
- 上限：投稿は1時間30件、返信は1時間60件、参加希望は1日10件

書き込みは本人セッションと同一Originが必須。Bearerトークンでは投稿も返信も参加希望もできない。本文はJSXで自動エスケープする。通報は通報者の画面で投稿を隠し`timeline_reports`に保存する。運営向けの通報処理は未整備。タイムラインは最新80件で、ページ送りは未実装。

## X型の画面 2026年11月8日

Home・Messages・プロフィール・SettingsをXの構成に合わせて作り直した。データの公開範囲と書き込みの規則は上記のまま。

- Home：中央600pxのカラムに絞り込みタブ（すべて・仲間募集・役割タグ）、アイコン付きの投稿欄、投稿一覧を置く。投稿はアイコン・表示名・@handle・相対時刻・本文・募集ブロック・作品カード・返信数と気になる数と参加したいの操作行で構成する。`HomePage`は右カラム用の`rail`を受け取り、1100px以下では下へ回す。作品数の表示は`WorkStatus`として切り出し、中央からは外した。プロフィールが空の利用者には上部に設定への導線を出す
- 投稿詳細：大きい本文と日時と件数の行、返信欄、返信のスレッド、募集なら参加希望の一覧
- Messages（`/connections`）：左に相手ごとの会話一覧、右に吹き出しのスレッド。会話は作品への質問と返信、誘い、仲間募集への参加希望を相手ごとに集約する（`TimelineStore.conversations`と`thread`）。誘いと参加希望はカードで表示し、受け入れ・見送り・取り消し・連絡先共有を会話から操作できる。会話を開くとその相手からの通知を既読にする
- Messagesの送信：新しいDMの保存先は作らず既存の仕組みに乗せる。相手からの未返信の質問があれば返信として保存し、なければ相手の共有作品への質問として保存する。どちらも作品ページで公開されることを入力欄に表示する。相手に共有作品がなく未返信の質問もない場合は送信できない
- 通知タブ：種類のアイコンと送り手のアイコンと相対時刻を表示し、質問・誘い・参加希望は会話へ、投稿への返信は投稿へ移動する
- プロフィール（`/u/:handle`）：CSSのバナー、アイコン、表示名、自己紹介、関心、リンク、Works（公開作品と年・タグの絞り込み）とPosts（本人の進捗・仲間募集と共有した作品）のタブ。ログインなしでも閲覧できる。Postsはこれまでログイン後のホームだけで見えていた投稿をログインなしにも公開する変更になる。ブロック関係にある閲覧者には表示しない
- Settings（`/settings`）：Profile（表示名・自己紹介・アイコン・関心16個まで・リンク6件まで）、Agent（旧`/settings/agents`の内容。旧URLは`/settings?tab=agent`へ転送）、Account（メールと公開IDとログアウト）。アイコンは作品画像と同じ検査（5MB・PNG/JPEG/WebPの署名）で保存し、プロフィールに設定した画像だけをログインなしで配信する

## 機会とClaude API

現状の候補発見は作品タグから外部検索するリンクと本人によるURL登録。公式サイトの自動巡回や募集情報の自動検証は行わない。保存時に開催日と締切と場所と条件と既存作品の可否を記録する。候補と応募済みと参加済みと見送りを分ける。機会の記録は所有者だけが閲覧できる。

AIは本人が選んだ1〜5件の作品と保存したイベント情報から適合理由と役割と題材と確認事項と次の作業を提案する。資料の再読解とポートフォリオ生成は引き続き外部のコーディングエージェントが担当する。機会への応募や外部SNSへの送信は行わない。

- `ANTHROPIC_API_KEY`：実行時の環境変数。値を設定ファイルやログに保存しない
- `ANTHROPIC_MODEL`：省略時は`claude-sonnet-5-5`
- Claude Messages APIとtool useで構造化した準備案を受信
- Zodで形式を検証し選択外の作品IDを拒否
- 根拠メモと担当判定メモと学校登録情報と画像ファイルを送らない
- 作品本文に個人情報を記入した場合は選択した本文とともに送られる
- リクエストは最大25秒で失敗時は再試行を案内
- 利用者ごとに24時間10回まで。同時リクエストを制限
- 同一のモデルと作品版と機会情報は成功結果を再利用
- 入出力トークン数と状態と生成時の入力をSQLiteへ保存
- 作品や条件が変わった場合は古い準備案であることを表示
- 60秒以上残った処理中状態は中断として再試行を案内

キーがなければAIボタンを無効にして未設定を表示する。ヒューリスティックの結果をClaudeの出力として見せない。実API呼び出しはこの環境では未検証。

仕様確認に[Claude Messages APIの公式リファレンス](https://platform.claude.com/docs/en/api/http/messages)を使用した。接続先は固定のAnthropic APIでありイベントURLをサーバーから取得しない。

## データ更新

新しい交流と機会のテーブルは`CREATE TABLE IF NOT EXISTS`で追加する。準備案の生成元を保存する`input_snapshot`列は`PRAGMA table_info`で存在を確認して追加する。旧レコードは未確認の生成元として扱う。元の利用者と作品と公開版のテーブルは変更しない。

公開停止と共有解除はSQLiteのtriggerで誘いと共有連絡先と通知に反映する。WebとAPIのどちらから停止しても同じ結果になる。質問の履歴は保存され共有を再開すると再表示する。

## 残る範囲

イベントの自動収集と個人の関心プロフィールとAIによる人物候補の提案は未実装。現段階では共有作品を本人が見て誘う。定期通知とメール通知とX連携とカレンダー連携も未実装。認証のメール確認と復旧とアカウント削除と運用バックアップを含めて外部公開前の作業が残る。
